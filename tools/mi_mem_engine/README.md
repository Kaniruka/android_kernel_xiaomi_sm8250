# Fixed AOSP15 warm/hot and cold producer

This directory contains real framework changes for **android-15.0.0_r1**, a native root helper, init definition, and platform-private SELinux fragments. Warm/hot launches begin on the successful launch event; cold launches keep the cookie pending until the process really attaches. It does not assert HyperOS source compatibility or on-device validation. Read production-plan.md for identity proof, the attach seam and cancellation linearization.

## ROM integration (Linux build host)

1. Install the matching kernel implementation and keep `include/linux/mi_mem_engine.h` byte-identical to its exported `include/uapi/linux/mi_mem_engine.h`.
2. Run `bash aosp/apply.sh /path/to/frameworks/base /path/to/frameworks/native`. It checks exact tag HEAD and patch applicability, then installs the four new Java files and two new JNI sources. `frameworks-base.patch` modifies real ActivityMetricsLogger, services JNI source list, and JNI registration. `frameworks-native.patch` adds ProcessState::dupDriverFD() using the existing Binder driver file, since AOSP15 exposes no existing driver FD getter; reopening /dev/binder would use a different handle namespace.
3. Copy this whole directory to `system/extras/mi_mem_engine` in the platform checkout. Add `mi_mem_engine_helper` to PRODUCT_PACKAGES. Merge `sepolicy/*.te`, file_contexts and property_contexts into platform **private** policy; do not install this system_server policy as vendor policy. The helper and init rc are installed by Soong.
4. Build `m services mi_mem_engine_helper selinux_policy` with the product's Android15 platform toolchain. JNI uses platform-private libbinder API, intentionally tied to this exact baseline.
5. Runtime defaults OFF. A trusted platform controller may set `sys.mi_mem_engine.enabled=1`; property `0` stops the service and closes/revokes the controller. Debug builds additionally permit shell to set this property. A system_server restart closes its socket; helper revokes the old controller before accepting a new client. Root-helper death/disable closes its device FD. No application receives the controller FD or socket authorization.

## Wire protocol

One 32-byte little-endian SOCK_SEQPACKET packet: u32 version=1, u32 op (1 BEGIN,2 END), u64 monotonic cookie, u32 uid, u32 lease_ms, u32 expected_main_tid, u32 binder_handle. BEGIN requires exactly one SCM_RIGHTS Binder-driver FD; END requires none. Replies are one little-endian signed errno (0 success). Oversize/truncated messages, excess FDs, bad versions and mismatched credentials are rejected; descriptors are closed on every path. Kernel validates the actual Binder driver file, its source UID1000 (the socket independently authenticates system_server), strong-reference handle, owning node process, exact expected TID/UID, version/layout, monotonically increasing cookie and lease.

Death registration is worker-owned, recorded only after link succeeds, and consumed before unlink. Lost prepare CAS and queued END share this idempotent cleanup; only the known missing-recipient exception is absorbed.

The init socket endpoint inherits the service domain `mi_mem_engine`; `file_contexts` independently labels its pathname `mi_mem_engine_socket`. Existing connectto and pathname permissions remain separate.

Warm/hot launches begin on the successful launch event. A cold launch mints a local launch identity in `notifyActivityLaunching`, binds the exact launched `ActivityRecord` in `notifyActivityLaunched`, and captures the identity of the process that really attaches in `MiMemEngineLaunch.attached(...)`, called from the existing `realStartActivityLocked` hook in `ActivityTaskSupervisor` through `ActivityMetricsLogger.notifyLaunchProfileAttached`. Drawn/abort, superseded coalesced launches, Binder death, warm-to-cold restart, timeout and socket/controller close revoke it. A pending cancellation suppresses BEGIN; an already committed BEGIN can finish before its queued END and is bounded by the lease. Old END is harmless and cannot disconnect or revoke a newer cookie. A warm-to-cold restart (`notifyBindApplication` with `mProcessRunning`) cancels the warm cookie and keeps coverage with a fresh pending cookie for the same record, so the cookie of a cancelled launch is never reused. Repeat attaches, a stale `ActivityRecord`, a replaced expected process and a UID mismatch never bind. A hosting record replaced before the worker revalidates under the WM lock cancels the session instead of leaving an attach claim with state 0, and the UID comparison is exact.

The controller cookie is handed out only when the serial worker commits BEGIN, so BEGIN cookies increase in actual submission order even when an older pending launch attaches after a newer warm launch; the kernel rejects any BEGIN whose cookie is not strictly greater than the last accepted one. Log lines carry the local `launch` identity plus the committed `cookie`. The helper opens the controller per accepted peer connection and `mme_open` resets `mme_last_cookie`, so an in-process counter only has to order BEGINs within one connection. `dupDriverFD` may return fd 0, so `-1` is the empty sentinel and `>= 0` is accepted in both the adapter and the transport. SurfaceFlinger input remains deferred ticket 13c.

## Kernel controller and allocator

Build `CONFIG_MI_MEM_ENGINE=y` explicitly; it defaults `n` and the controller defaults OFF even when built. `/dev/mi_mem_engine` is mode 0600 and every open/ioctl requires CAP_SYS_ADMIN in the initial user namespace. Only one open controller is allowed. ENABLE uses lease_ms 0/1; BEGIN uses strictly increasing nonzero cookies, 1–4 Binder identities and a 1–1000ms lease. END clears only a matching active cookie and otherwise succeeds without changing the newer scene. Disable/close publishes an empty scene. RCU readers already in flight may finish one legitimate allocation; old identities are dropped only after the RCU grace period.

The fixed 88-byte v1 request has a 24-byte header and four 16-byte tasks (`binder_fd`, `binder_handle`, expected main `tid`, `uid`). No pointers or native-width fields cross the ABI. Unknown commands, incorrect size/version, replayed BEGIN cookies, extra task data, wrong Binder file type, missing/dead Binder node owner, or UID/TID mismatch fail closed. PID values only verify the stable node owner; they are never looked up asynchronously. The snapshot retains a `struct pid` reference, one RCU-protected UID value and exact immutable `task->real_start_time` nanoseconds. Allocator reads check all three against current. Expiry uses boottime and stops matching at the deadline even if deferred cleanup is delayed; task exit schedules cleanup. All writers serialize through one mutex, while allocator reads take only RCU.

Only ordinary sleepable order-0 allocations qualify. HIGH/HARDER/OOM/no-watermark reserve flags, PF_MEMALLOC, atomic/IRQ-disabled contexts, and privileged GFP flags are excluded. The local mark changes after the existing min-watermark boost exception, immediately before `zone_watermark_fast`, by `mark -= mark/4` (101→76). The same mark is reused for the existing zone recheck; all existing rmqueue/reclaim/fallback and memcg logic remains. No global watermark, OOM policy or reserve pool ownership is changed. C21/C22 page pools remain independent; C22's future watermark policy requires separate arbitration and is not implemented by this slice.

With trace events available, `mi_mem_engine:mme_allocation` records eligible requests' cookie, tid, original/effective mark and hit flag. This is an observation hook, not evidence of an on-device launch or performance improvement. The host test `tools/testing/selftests/dagu/mem_engine/session.c` compiles the production ABI policy and checks strict request validation, replay rejection, exact deadline boundary, old-END matching and 101→76. It does not emulate Binder lifetime, RCU or an Android runtime.

Algorithm provenance: conservative independent adaptation of `drivers/staging/mi_mem_engine/unfairmem.c` by huzhongyang, MiCode/Xiaomi_Kernel_OpenSource bixi-v-oss commit `56295df675b92553f83bbf333f88b0c6ee8fa7bc` (GPL; repository GPL-2.0). The source evidence remains in the workspace C06 evidence bundle. Target restrictions, controller, lifetime and Binder identity bridge are new implementation, with no claim that HyperOS already connects to this ABI.
